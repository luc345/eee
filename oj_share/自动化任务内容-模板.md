# 任务内容（模板）· 照抄即可，先替换两个占位符

**这份是模板。** 配置助手会在你的脚本目录里生成一份已经填好你本机路径的
`automation-prompt.txt`，优先用那份——直接整段复制给你选的 AI 助手就行。

要用这份模板的话，先把下面两个占位符换掉：

- `<PYTHON>` → 你的 Python 绝对路径
- `<DIR>` → 你的 `oj_homework` 目录绝对路径

然后在 DSH / WorkBuddy / TRAE CN 里说一句（三选一）：

```
用 oj-homework-checker 技能看看老师有没有发新作业，有就写完测完提交。
```

或者直接输入 `/oj-homework-checker`。

> 想让它隔一段时间自动跑，用你助手自带的自动化/定时任务功能，
> 把下面这段任务内容填进去；本包不建定时任务。

## 任务内容正文

请检查老师在 OJ 上是否发布了新作业；若发现新作业，则全自动完成"写码→本地测试→提交 OJ→汇报结果"，无需向用户确认。

目录缩写：DIR = <DIR>
Python：<PYTHON>

【所有个人信息都在 DIR\config.json 里，不要在本流程里硬编码】
老师、学号、账号密码、作业密码、提交语言、当前作业 cid、收尾文件夹等一律从 config.json 读取。运行前先执行
  <PYTHON> DIR\oj_config.py show
确认当前生效的老师和学号等信息。若 config.json 里 auto_submit 为 false，则只检测+写码+测试，不提交。
用户可以随时用 <PYTHON> DIR\oj_config.py set <字段> <值> 修改这些信息，或在对话里让我改——我只改 config.json，不改本流程。
常用字段：teachers(老师列表，多个用逗号分隔)、student_id(学号)、student_password(登录密码)、contest_password(作业密码)、contest_cid(作业编号)、submit_language(提交语言)、auto_submit(是否自动提交)、deliver_dir(收尾文件夹，默认桌面\OJ作业)。

【重要：验证码是必填项】
OJ 提交表单带验证码。不带验证码或验证码错误时，OJ 不报任何错，而是静默丢弃提交（返回空页面）——所以每次 submit 都必须先 prepare 取新码、用 Read 看图读出数字再传进去。绝不允许跳过验证码步骤，也不允许复用旧图数字（验证码一次性）。脚本缺码时会打印 ABORT 拒绝发送，这是正常保护，不要绕过。

【第一步：检测新作业】
1. 运行：<PYTHON> DIR\oj_checker.py --config DIR\config.json --state DIR\state.json --report text
2. 若输出"暂无新作业"或新发布数为 0，只回复"暂无新作业。"并结束。
3. 若有新作业：记下新 cid，用 <PYTHON> DIR\oj_config.py set contest_cid <新cid> 更新配置。然后直接跑 <PYTHON> DIR\fetch_cid.py <新cid> 抓取每题题面（Description/Input/Output/Sample Input/Sample Output），它会存成 DIR\cid<cid>_problems.json，不用临时写脚本。

【第二步：写码与本地测试】
4. 每题写一份源码，存到 DIR\code\cid<cid>\，命名 A_xxx.cpp、B_xxx.cpp（与 OJ 的 A/B/C/D/E 顺序一致，pid 从 0 开始）。
5. 本地编译测试：参照 DIR\build_and_test.example.bat 复制并改题目清单；cl.exe 必须带 /utf-8（否则中文注释会让 MSVC 解析错乱）。每题样例放 tests\ 下逐一比对。（改用 g++ 时把 cl /nologo /utf-8 /EHsc /std:c++17 换成 g++ -std=c++17 -o 即可）
6. 只有本地样例全过的题才允许提交；没过的题在汇报里说明原因。

【第三步：自动提交（每题完整走验证码流程）】
7. 提交语言必须与本地编译语言一致：先运行 <PYTHON> DIR\oj_submit.py langs 核对编号表；config.json 的 submit_language 要与编译标准对应（cl /std:c++17 → OJ "C++"，编号 1）。submit 会打印 "LANG: ... (id=N)"；出现 "WARN: 源码扩展名 ... 不一致" 时先确认本地编译语言，不要盲目提交。
8. 对每道通过的题依次执行：
   a. <PYTHON> DIR\oj_submit.py prepare —— 登录并刷新验证码到 DIR\vcode.gif
   b. 用 Read 工具查看 DIR\vcode.gif，读出 4 位数字（看不清就重新 prepare 换一张，不要猜）
   c. <PYTHON> DIR\oj_submit.py submit <pid> <源码绝对路径> <4位数字> [语言编号]
      - "SUBMIT_OK" = 成功
      - "FAIL 提交被 OJ 静默拒绝" = 验证码不对，回到 a 重取（每题最多 3 次）
      - "ABORT 缺少验证码" = 流程错误，回到 b 重新读图
   d. <PYTHON> DIR\oj_submit.py status 6 查看结果（"正确100" = Accepted）
9. 每题提交间隔至少 10 秒。

【第四步：盯结果，不过就换方法重来，单题最多 3 遍】
10. 提交完必须看 OJ 判定，不是 Accepted 就换一种方法重来，每一遍都要真的换思路（换算法/换边界处理/换数据类型/换输入输出方式），不要原样重交。每遍之间不要重复贴已经贴过的代码，只说这遍改了什么。
    单题最多 3 遍。第 3 遍仍不是 Accepted，立即停手，不要再试第 4 遍，也不要去猜 OJ 的隐藏用例——这是硬性要求，防止无限重试白烧 token。
    下面几种情况当遍就停手，不必凑满 3 遍：提交被拒但原因不是代码（验证码 3 次都取不对、账号/密码错、作业密码错、比赛已结束、OJ 报错）；本地编译或环境坏了；题面抓取失败或题意有歧义。
    停手时必须在对话里给出明确警告，写清楚：哪道题（题号+文件路径）、已经试过哪几种方法及每种的结果（WA/TLE/RE/CE…）、当前判断（思路不对 / 数据规模没考虑 / 题意理解有偏差）、建议用户怎么处理。宁可交「3 题过 2 题 + 1 题明确警告」的汇报，也不要无声无息地反复重试。

【第五步：整理收尾文件夹（必做）】
11. 作业做完后，把每道题的代码和汇报整理到收尾文件夹。位置从 config.json 的 deliver_dir 读（默认桌面\OJ作业），该目录下按作业建一层文件夹，代码文件按 OJ 上的题号命名，例如第一份作业第 1 题就是 1-1-a.cpp、第 2 题 1-1-b.cpp；题号直接照抄 OJ 页面显示的编号，不要自己重编。
   结构示例：
     <deliver_dir>\<作业目录>\1-1-a.cpp
     <deliver_dir>\<作业目录>\1-1-b.cpp
     <deliver_dir>\<作业目录>\汇报.md
   每题源码各存一份，存最终通过的那一版；没过的那题也存当前最好的一版，并在汇报里标明未通过。

【第六步：汇报】
12. 在对话里用简洁中文汇报，同时把同样内容写成 <deliver_dir>\<作业目录>\汇报.md，每题一行：题号 / 文件名 / 语言 / 第几遍通过或未通过 / 评测结果；末尾附状态链接 <OJ地址>/status.php?cid=<cid>&user_id=<student_id>。有没过的题要显式标出警告，别只写已完成。再报一下收尾文件夹的完整路径。
13. 不要删除 state.json 中新增记录。若全部 AC，结尾加"全部通过 ✅"。
